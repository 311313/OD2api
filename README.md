# OD2api

把上游 AI 编码服务的账号池包装成 OpenAI 兼容接口。

多个账号轮着用：哪个有钱用哪个，谁触发限流就歇一会儿。下游拿一个 API 地址 + 一个 key 就能用，不用管后面有几个号。

## 能干什么

- **账号池调度**——按余额、日限额、请求间隔自动选号；坏了的号自动冷却、自动恢复
- **粘性会话**——同一对话钉在同一个号上，上游的缓存能复用，省钱
- **按模型计价**——每个模型单价单独实测过（含缓存折扣），日志里能看到每个请求花了几积分
- **管理面板**——账号、分组、密钥、请求日志、统计，全在网页上操作
- **一键部署**——`scripts/deploy.py`，带健康检查，坏了自动回退
- **自动更新**——服务器上装好 cron 后，push 到仓库就自动拉取重启

## 跑起来

```bash
docker compose up -d --build
```

面板在 `http://127.0.0.1:7890`，管理令牌首次启动随机生成（docker logs 里有一行提示），面板设置页可以查看和轮换。

## 目录

```
src/          网关本体（Node 24 + Express + node:sqlite）
public/       面板（原生 HTML/JS，无构建）
docs/         费率测量方法与数据、运维问题记录
scripts/      部署、备份、回归测试
```

## 环境变量

都可选，见 `.env.example`。数据库在 `data/`，重启不丢。

## 说明

- 上游服务本身的客户端是闭源的，接口行为靠抓包实测，见 `docs/`
- 上游如果改协议，这里要跟着改；`docs/incidents.md` 记了踩过的坑
